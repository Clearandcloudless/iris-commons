# Documentation

`docs/` contains explanatory, educational and implementation-supporting documents.

Use this directory for:

- onboarding and usage guides;
- conceptual explanations;
- architecture notes that are not normative specifications;
- threat models and design analysis;
- tool integration instructions.

Do not use this directory as an unstructured submission inbox. New ideas and questions should begin as Issues.

A document in `docs/` explains the project but is not automatically a binding rule. Current normative protocols belong in `specs/`; accepted governance decisions belong in `governance/` or `decisions/`.

Existing files in this directory predate the formal repository-routing policy. They remain valid until moved or reclassified through focused Pull Requests.
